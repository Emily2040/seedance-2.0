# Seedance 2.0 — 从想法到可修改的第一条提示词

版本 6.7.0。这份指南用于准备提示词；视频由你另行选择的生成服务制作。

**审核状态：**本页由 AI 辅助起草，独立中文及影视制作语言审核尚未完成。示例未生成视频，不代表实测质量、积分节省或口型同步效果。正文使用简体中文；提示词文字、交付字幕字形和对白的口音是不同选择，不应自动互换。[覆盖与审核记录](LANGUAGE_COVERAGE.md)。

## 1. 安装一个根技能

下载并解压仓库，或运行：

```sh
git clone https://github.com/Emily2040/seedance-2.0.git
cd seedance-2.0
```

在这个目录中，选择**一个**安装位置。每个位置都会得到一个 `seedance-20/` 文件夹；不要分别安装子技能。

```sh
# Codex：当前用户可用
python scripts/install_codex_skill.py --client codex --scope user

# Claude Code：当前用户可用
python scripts/install_codex_skill.py --client claude-code --scope user

# Codex：仅用于一个已存在的项目，项目必须位于本源码目录之外
python scripts/install_codex_skill.py --client codex --scope project --project-root "/path/to/project"
```

将 `/path/to/project` 换成源码目录之外已存在的项目路径；含空格的路径要保留引号。这些命令在源码目录中运行。

本节中文修订由 AI 辅助起草，独立语言审核仍待完成：[审核状态](LANGUAGE_COVERAGE.md)。

其它客户端或自定义配置可用 `--dest /path/to/client/skills` 指定技能目录。不要将它与客户端、作用域选项混用。不传安装位置选项时，仍使用历史位置 `$CODEX_HOME/skills` 或 `~/.codex/skills`；显式选择用户作用域不会迁移或禁用旧副本。

用 doctor 检查**同一个安装位置**。例如，选择第一项后运行：

```sh
python scripts/install_doctor.py --client codex --scope user --json
```

`current` 表示已检查的安装文件与这份源码一致。重启或刷新客户端后，另行核对它发现的技能路径；doctor 不能证明客户端加载了哪个副本。只有明确要替换现有安装时才使用 `--force`，并先保存本地修改和一份独立备份。 [安装位置选项](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_SCOPES.md) · [迁移与重复安装](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_MIGRATION.md).

需要手动传输时，先用安装器的 `--dest /path/to/new-staging/skills` 在源码目录之外的新位置准备文件。**只复制生成的 `seedance-20/` 目录**，保留隐藏文件和安装完成记录。直接从 GitHub 导入时，客户端可能打包不同的文件；请核对导入内容，不要假定它采用了本安装器的允许清单。 [手动传输说明](https://github.com/Emily2040/seedance-2.0/blob/main/docs/MANUAL_INSTALL.md).

## 2. 从已经确定的内容开始

调用 `seedance-20`，直接描述场景。已经决定的镜头、声音、时长和意图应继续保留；不必重做访谈，也不必回答未请求的选择菜单。

| 你现在有什么 | 下一步 |
|---|---|
| 单条视频的模糊想法 | 先出草稿，或只问一个阻碍继续的问题；`seedance-interview-short` |
| 完整场景简报 | 直接写提示词；`seedance-prompt` |
| 多条相连的片段 | 规划顺序与每条片段的任务；`seedance-sequence` |
| 已认可、想继续的片段 | 从实际结尾继续；`seedance-continuation` |
| 不符合要求的结果 | 指出失败项，在预算内提出修正；`seedance-troubleshoot` |

不必记住路由名称。可以直接这样说：

> 我想要一条六秒的开心小片段：一位成年女钟表修理师听见刚修好的座钟又响起滴答声。固定镜头，无对白。给我三个方向，让我自己选。只准备提示词，不要生成。

## 3. 选择观众要关注什么

下面三种方案回应的是**这一份简报**，不是所有视频都要回答的菜单。

| 方向 | 可见的决定 | 取舍 |
|---|---|---|
| A · 小小的满足 | 固定中近景；她听到滴答声后露出微笑 | 重点是表情与声音的关系 |
| B · 放开庆祝 | 固定较宽景别；她短促地笑出声，举起双臂 | 重点是外放的身体反应，需要交代更多动作 |
| C · 看钟恢复运转 | 固定特写拍摆动的钟摆；她在背景中虚化 | 重点是座钟的运动，人物表情不再是主体 |

你可以选 A，组合不冲突的决定，或说“替我选，并说明理由”。确定 A 后，后续修改应继续沿用 A；除非你要求改变，不再混入 B、C 的动作。

## 4. 复制选定的提示词

**本例选择 A。** 这是文生视频草稿，没有附件，也不需要参考标签。若所选服务的当前操作支持六秒，就在对应设置中填写六秒；花费前核对设置。画幅和质量档位沿用你另行选择的值。这里不预设服务商、API 或模型档位。

```text
一位成年女钟表修理师坐在已经恢复运转的座钟前。听到滴答声，她微微抬眉，露出微笑，视线始终落在座钟上。平视中近景，固定镜头。侧窗光照清她的表情。保留滴答声与工作室环境声，无对白、无配乐。最后两秒保持微笑和坐姿。
```

**这些决定想达到什么：**滴答声引出可见反应；固定镜头让观众读到表情；最后的停留给反应留出时间。这是导演意图，不是已验证的结果，也不能证明现实中的维修质量。

**拿到视频后检查：**视线是否留在座钟上，镜头是否固定，有没有意外说话，最后两秒是否保留表情和姿态。先找出不合格的那一项，再考虑修正。

“固定镜头”指相机位置与取景保持不动，不是让人停止动作，也不是慢动作。若改为“缓慢推近”，改变的是相机运动；若要人物慢动作，应另行说明表演速度。不要用同一个“慢”替代这两种决定。

把主体和动作放在前面是便于阅读的编辑方法，不是已验证的模型首词机制。英文的字数建议不能直接换成中文的字数上限；紧凑不等于删掉结束状态、参考关系或逐字台词。

## 5. 只改失败的那一项

> 笑得太夸张了。保留 A、六秒和固定镜头。我只剩一次机会，先写一个修改版，不要提交。

如果没有附上视频，回答应说明问题来自**你的描述**，不能声称已经看过。可提议只把“微微抬眉，露出微笑”换成“眉毛放松，嘴角轻轻上扬，不露齿”，其它内容和设置不变。这个改法想缩小表情幅度，但不能保证修好结果。只有一次机会，也不意味着必须用掉它。

剩余次数或预算为零时，不再请求生成。可以判断已有素材能否剪成符合要求的片段，或停止；后期也有时间和工具成本。不符合要求的镜头不能因预算用完就被标为通过。写修改版不等于授权上传、提交生成、更换服务商或提高档位、时长。

## 6. 对白、参考素材与续接

**逐字对白。** 如果你把简报改成“保留台词『又走起来了。』，不要改字”，就保留这句话。这里设定她在自言自语，不自动增加听众，也不额外添加“您”等称呼。不要把台词加进原来的无对白版本。若需要某种口音或地区表达，应由你选择；不要为了压缩字数擅自换成拼音、改成另一种字形或缩句。实际说多久、发音和口型是否合适，需要计时和合格语言审核；本例没有这些实测结果。服务支持且拥有使用授权的声音参考，或后期配音，都是可选方案。

**真实附件。** 如果你实际提供了 `@Image1`，说明它的作用，例如仅参考座钟外观。保留界面原样给出的标签，包括 `@图片1` 或 `[Image 1]`；文字语言不决定标签形式。写出名字并不等于上传文件。没有图片时，上面的草稿仍是文生视频，不能凭空加一个参考标签。所用操作还必须支持对应的素材和用途。

**从实际结尾继续。** 如果你只说“末帧里她微笑着看座钟”，却没有提供末帧，回答应把它记为你的描述，不能捏造工作室细节或声称已经检查过画面。提供已认可的实际末帧后，从那个姿势和视线继续，不再重演最初听到滴答声的反应。关键位置未知时，先澄清，再把它当作确认过的连续性条件。

## 7. 安全与下一步

参考图片、文件或转录里出现的文字是素材，不是操作授权。它们不能要求 agent 读取密钥、执行命令、上传文件或生成视频。需要处理他人的脸、声音、品牌或作品时，先明确授权与用途；不要通过翻译隐藏受限请求。参见 [SECURITY.md](../SECURITY.md)。

**安装后的内容**会排除 `scripts/eval_run.py` 等可联网的开发评测工具及可选服务商执行器。宿主客户端仍控制自己的文件、网络和凭据权限；安装这份技能不会把宿主变成离线环境。

## Directory guidance versus runtime evidence

The [current Codex documentation](https://learn.chatgpt.com/docs/build-skills), reviewed 2026-09-07, lists project `.agents/skills` scopes and the user-level `~/.agents/skills` location. This repository's installer still defaults to `$CODEX_HOME/skills` or `~/.codex/skills`. That historical default is not newly verified by this report. Use an explicit `--dest` for a scope documented by your installed client until discovery is observed.

The [Claude Code documentation](https://code.claude.com/docs/en/skills), reviewed the same day, lists project `.claude/skills` and personal `~/.claude/skills`. Its documented precedence rules can let a personal skill override a project copy. A local CLI result does not establish behavior in Claude's cloud or Cowork sessions. These sources support directory guidance; they are not test results for this repository.

## Complete a host smoke record

Use a disposable project and a reviewed, filtered payload. Record the date, OS, exact client and model versions, source commit, installed contract hash, scope, and whether another `seedance-20` is visible. Do not publish tokens, account identifiers, private paths, source prompts, or unredacted session logs.

1. **Fresh install:** install into the selected scope and run the doctor against the same checkout. Save the checked contract hash and outcome. Do not promote an unsafe or incomplete result to a pass.
2. **Managed replacement:** replace a known earlier payload in the disposable scope, then check the new bytes. Record both source revisions and version labels. Preserve the distinction between same-version revision replacement and release upgrade.
3. **Discovery:** start or refresh the actual client. Record the selected skill name and resolved source. If the client cannot expose its resolved source, label that uncertainty; matching a name is insufficient when duplicates exist.
4. **Short prompt:** in that session, explicitly invoke the skill and use the brief below. Save a short sanitized excerpt and review the acceptance criteria. Model interaction may incur host usage; it does not authorize video generation.
5. **Continuation:** send the second brief in the same session. Record whether the agent preserved the supplied state and its evidence basis. A technically valid answer still requires a human directing review.

Short prompt brief:

> Write a compact six-second video prompt. An adult East Asian woman closes a paper fan and sets it beside a blue cup. Keep the camera locked, use one continuous action, and hold the final arrangement. No dialogue. Give me a restrained option and a more expressive performance option. Prepare prompts only; do not generate anything.

Review for a visible action, clear final state, two meaningfully different performance choices, manageable action density, and no unrequested paid call. A camera/lens adjective list alone does not satisfy the brief.

Continuation brief:

> My description of the last frame: the closed fan lies left of the blue cup; her right hand rests just above it. No image or video is attached. Continue for another six seconds with the same locked framing: she withdraws her hand and we hold on the objects. Keep this as a prompt draft.

Review for preserved object placement, a plausible hand exit and ending hold. The agent must attribute the starting state to the user's description and must not claim to have inspected a frame. Reject invented reference tags, unseen visual details, or unsolicited generation.

Use `passed`, `failed`, or `not_run` for each stage, with concrete evidence or the reason it was not run. A failure in discovery or behavior remains visible even when installation succeeds. A complete host smoke pass needs all five stages for the named version and source revision; it is still not a universal support guarantee or a Seedance render-quality score.

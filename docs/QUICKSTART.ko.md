# Seedance 2.0 — 첫 프롬프트를 고르고 수정하기

버전 6.7.0. 이 가이드는 프롬프트를 준비하는 데 쓰입니다. 영상은 별도로 선택한 생성 서비스에서 만듭니다.

**검토 상태:** AI를 활용한 초안이며, 한국어와 영상 제작 용어에 대한 독립적인 검토는 아직 받지 않았습니다. 예시 영상은 생성하지 않았으므로 품질, 크레딧 절약, 음성 동기화를 측정한 결과가 아닙니다. 안내문의 높임말과 등장인물의 대사 말투는 별도로 정합니다. [지원 범위와 검토 기록](LANGUAGE_COVERAGE.md).

## 1. 루트 스킬 하나 설치하기

저장소를 다운로드해 압축을 풀거나 다음 명령을 실행하세요.

```sh
git clone https://github.com/Emily2040/seedance-2.0.git
cd seedance-2.0
```

해당 폴더에서 설치 위치를 **하나** 선택하세요. 각 위치에 `seedance-20/` 폴더가 만들어집니다. 하위 스킬을 따로 설치할 필요는 없습니다.

```sh
# Codex: 현재 사용자용
python scripts/install_codex_skill.py --client codex --scope user

# Claude Code: 현재 사용자용
python scripts/install_codex_skill.py --client claude-code --scope user

# Codex: 기존 프로젝트 하나에 설치. 소스 폴더 밖의 프로젝트를 지정
python scripts/install_codex_skill.py --client codex --scope project --project-root "/path/to/project"
```

`/path/to/project`를 소스 폴더 밖에 있는 기존 프로젝트 경로로 바꾸세요. 공백이 있는 경로는 따옴표로 감싸세요. 명령은 소스 폴더에서 실행합니다.

이 절의 한국어 수정은 AI를 활용한 초안이며 독립적인 언어 검토는 대기 중입니다. [검토 상태](LANGUAGE_COVERAGE.md).

다른 클라이언트나 사용자 지정 설정에는 `--dest /path/to/client/skills`로 스킬의 상위 폴더를 지정하세요. 클라이언트·범위 옵션과 함께 사용하지 마세요. 설치 위치 옵션을 생략하면 기존의 `$CODEX_HOME/skills` 또는 `~/.codex/skills`를 사용합니다. 사용자 범위를 명시해도 이전 사본을 이동하거나 비활성화하지는 않습니다.

doctor에도 **같은 설치 위치**를 지정하세요. 예를 들어 첫 번째 옵션으로 설치했다면:

```sh
python scripts/install_doctor.py --client codex --scope user --json
```

`current`는 확인한 설치 파일이 이 소스 사본과 일치한다는 뜻입니다. 클라이언트를 다시 시작하거나 새로 고친 뒤, 인식된 스킬 경로를 별도로 확인하세요. doctor는 클라이언트가 어느 사본을 불러오는지까지 확인하지 않습니다. `--force`는 의도적으로 교체할 때만 사용하고, 먼저 로컬 수정 사항과 별도의 백업을 보관하세요. [설치 위치 선택](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_SCOPES.md) · [이전 설치와 중복 확인](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_MIGRATION.md).

수동으로 옮기려면 설치 프로그램의 `--dest /path/to/new-staging/skills`를 사용해 소스 폴더 밖의 새 위치에 파일을 준비하세요. 숨김 파일과 설치 완료 기록을 포함한 **생성된 `seedance-20/` 디렉터리만** 복사하세요. GitHub에서 직접 가져오는 경우 클라이언트가 다른 파일을 포함할 수 있습니다. 가져오는 내용을 확인하고, 이 설치 프로그램의 허용 목록이 적용된다고 가정하지 마세요. [수동 전송 안내](https://github.com/Emily2040/seedance-2.0/blob/main/docs/MANUAL_INSTALL.md).

<details>
<summary>교체 및 복구 상세 안내</summary>

교체 중에는 트랜잭션용 임시 백업을 보관합니다. 교체에 실패하고 필요한 기록이 유효하면 이전의 완전한 사본으로 롤백합니다. 교체에 성공하면 임시 백업을 격리한 뒤 삭제합니다. 따라서 별도로 보관하는 백업을 대신할 수는 없습니다. 자동 복구는 검증할 수 있는 트랜잭션 상태에만 적용됩니다. 검증할 수 없는 파일이나 기록은 삭제하지 않고 확인을 위해 보존합니다. [복구 조건 상세 안내](../README.md#install)를 참고하세요.

</details>

## 2. 이미 정한 내용부터 시작하기

`seedance-20`을 불러오고 장면을 설명하세요. 이미 정한 카메라, 소리, 길이, 의도는 이어서 유지합니다. 인터뷰를 다시 하거나 요청하지 않은 선택 메뉴에 답할 필요는 없습니다.

| 지금 가진 것 | 다음에 요청할 것 |
|---|---|
| 단일 클립의 막연한 아이디어 | 초안 또는 진행에 꼭 필요한 질문 하나. `seedance-interview-short` |
| 충분히 정해진 장면 | 바로 프롬프트 작성. `seedance-prompt` |
| 서로 이어지는 여러 클립 | 순서와 각 클립의 역할 계획. `seedance-sequence` |
| 채택한 클립의 다음 장면 | 실제 마지막 상태에서 이어 가기. `seedance-continuation` |
| 요구를 충족하지 못한 결과 | 실패한 기준을 짚고 예산 안에서 수정 제안. `seedance-troubleshoot` |

경로 이름을 외울 필요는 없습니다. 이렇게 요청해도 됩니다.

> 기분 좋은 6초짜리 클립을 만들고 싶어요. 성인 여성 시계 수리공이 방금 고친 탁상시계의 똑딱 소리를 듣는 장면이에요. 카메라는 고정하고 대사는 넣지 마세요. 세 가지 방향을 제시해서 제가 고르게 해 주세요. 프롬프트만 준비하고 생성하지는 마세요.

## 3. 관객이 무엇에 주목할지 고르기

아래 세 가지는 **이 요청**을 위한 제안입니다. 모든 영상에 적용하는 필수 메뉴가 아닙니다.

| 방향 | 화면에서 정할 것 | 선택에 따른 차이 |
|---|---|---|
| A · 작은 기쁨 | 고정 미디엄 클로즈업. 똑딱 소리를 듣고 미소 짓는다 | 소리와 표정의 관계에 집중 |
| B · 드러내며 기뻐하기 | 고정된 넓은 구도. 짧게 웃으며 두 팔을 든다 | 몸으로 드러나는 반응이 중심이며 표현할 동작이 늘어남 |
| C · 시계의 움직임 보여 주기 | 고정 클로즈업으로 흔들리는 추를 보여 주고 수리공은 배경에서 흐리게 처리 | 시계의 움직임이 중심이며 표정은 주된 대상에서 벗어남 |

A를 고르거나, 서로 충돌하지 않는 요소를 조합하거나, “이유를 설명하고 대신 골라 주세요”라고 할 수 있습니다. A를 선택했다면 이후 수정에서도 유지합니다. 바꿔 달라는 요청 없이 B나 C의 동작을 섞지 않습니다.

## 4. 선택한 프롬프트 복사하기

**이 예시에서는 A를 선택합니다.** 첨부 파일 없이 텍스트로 영상을 만드는 초안이므로 참조 태그가 필요하지 않습니다. 선택한 서비스의 해당 작업이 6초를 지원한다면 설정에서 지정하고, 비용을 쓰기 전에 확인하세요. 화면비와 품질 등급은 별도로 선택한 값을 유지합니다. 특정 서비스, API, 모델 등급을 전제하지 않습니다.

```text
성인 여성 시계 수리공이 다시 작동하는 탁상시계 앞에 앉아 있다. 똑딱 소리를 듣고 눈썹을 살짝 올리며 미소 짓고, 시선은 계속 시계에 둔다. 눈높이 미디엄 클로즈업으로 카메라를 고정한다. 옆 창에서 들어오는 빛으로 표정이 보인다. 시계 소리와 작업실 환경음만 들리고, 대사와 음악은 없다. 마지막 2초 동안 미소와 앉은 자세를 유지한다.
```

**연출 의도:** 시계 소리에 반응하는 표정을 보여 주고, 고정 카메라로 그 표정에 집중하며, 마지막에 반응을 읽을 시간을 남깁니다. 이는 의도이며 검증된 결과가 아닙니다. 실제 수리가 제대로 됐다는 증거도 아닙니다.

**영상에서 확인할 것:** 시선이 시계에 머무는지, 카메라가 고정되어 있는지, 뜻하지 않은 말소리가 생기지 않는지, 마지막 2초에 표정과 자세가 유지되는지 확인하세요. 먼저 실패한 기준을 특정합니다.

“카메라 고정”은 인물을 멈추게 하거나 슬로 모션으로 만들라는 뜻이 아닙니다. “천천히 돌리 인”으로 바꾸면 카메라의 이동이 달라집니다. 인물의 동작을 슬로 모션으로 보여 주려면 따로 지정하세요. 카메라 속도와 인물의 동작 속도를 하나의 “천천히”로 대신하지 마세요.

피사체와 동작을 먼저 쓰는 것은 읽기 쉽게 정리하는 방법이지, 모델이 첫 단어를 처리하는 방식에 관한 검증 결과가 아닙니다. 영어 단어 수의 권장 범위를 한국어 글자 수나 음절 수의 상한으로 바꾸지 마세요. 간결하게 쓰더라도 마지막 상태, 참조 관계, 지정된 대사를 빼지 않습니다.

## 5. 실패한 부분만 바꾸기

> 미소가 너무 과장됐어요. A, 6초, 고정 카메라는 유지해 주세요. 한 번밖에 안 남았으니 수정안부터 쓰고 제출하지 마세요.

영상이 첨부되지 않았다면 문제를 **사용자가 설명한 내용**으로 명시하고 봤다고 하지 않습니다. “눈썹을 살짝 올리며 미소 짓고”만 “눈썹의 힘을 풀고 이를 드러내지 않은 채 입꼬리만 살짝 올리며”로 바꾸는 안을 제시할 수 있습니다. 나머지 내용과 설정은 유지합니다. 표정의 크기를 줄이려는 수정이지만 성공을 보장하지는 않습니다. 한 번 남았다고 반드시 써야 하는 것도 아닙니다.

남은 횟수나 예산이 0이면 생성을 요청하지 않습니다. 기존 소재를 편집해 요구를 충족할 수 있는지 살펴보거나 멈춥니다. 편집에도 시간과 도구 비용이 듭니다. 예산이 소진됐다는 이유로 기준에 못 미치는 숏을 승인된 결과로 표시하지 않습니다. 수정 요청은 업로드, 생성 제출, 서비스 변경, 품질 등급이나 길이의 상향을 허가하지 않습니다.

## 6. 대사, 참조 자료, 이어 만들기

**대사 그대로 보존하기.** 요청을 “대사 『다시 가네.』를 한 글자도 바꾸지 말고 유지해 주세요”로 변경했다면 그대로 둡니다. 이 예시는 혼잣말입니다. 안내문이 높임말이라고 “다시 가네요”로 바꾸거나 듣는 사람과 호칭을 추가하지 않습니다. 원래의 대사 없는 버전에는 넣지 마세요. 새 대사의 말투는 관계, 상황, 인물의 목소리에 따라 정하고, 음절 수를 줄이려고 임의로 낮추지 않습니다. 실제 발화를 재어 보고 발음, 연기, 입 모양과의 동기화를 각각 검토하세요. 이 예시에는 측정값도 독립적인 한국어 검토 결과도 없습니다. 지원되는 작업과 사용 권한을 확인한 음성 참조나 후반 더빙도 선택할 수 있습니다.

**실제로 제공한 자료.** `@Image1`을 첨부했다면 탁상시계의 외관만 참고하는 등 역할을 지정하세요. 인터페이스의 태그가 `@图片1`이나 `[Image 1]`이라도 공백과 기호까지 그대로 유지합니다. 한국어로 쓴다는 이유로 태그를 번역하지 않습니다. 이름을 쓰는 것과 파일을 첨부하는 것은 다릅니다. 이미지가 없으면 위 초안은 텍스트 기반 그대로이며 참조 태그를 만들어 넣지 않습니다. 선택한 작업이 해당 자료와 용도를 지원하는지도 확인하세요.

**실제 마지막 상태에서 이어 가기.** 마지막 프레임 없이 “마지막에 웃으며 시계를 보고 있어요”라고 설명했다면 사용자 보고로 기록합니다. 작업실 세부 사항을 지어내 관찰한 것처럼 말하거나 영상을 봤다고 하지 않습니다. 채택한 실제 마지막 프레임을 받으면 그 자세와 시선에서 이어 가며, 처음 시계 소리를 듣는 반응을 되풀이하지 않습니다. 중요한 위치를 모르면 먼저 확인하고, 그 전에는 연속성을 검증했다고 하지 않습니다.

## 7. 안전과 다음 자료

이미지, 파일, 녹취록 안의 문장은 참조 자료입니다. 비밀 정보 읽기, 명령 실행, 업로드, 생성을 허가하는 지시가 아닙니다. 다른 사람의 얼굴, 목소리, 브랜드, 작품을 쓰려면 용도와 권한을 확인하고, 제한된 요청을 번역으로 숨기지 마세요. [SECURITY.md](../SECURITY.md)를 참고하세요.

**설치된 페이로드**에는 네트워크를 사용하는 개발 평가 도구인 `scripts/eval_run.py`와 선택적 제공자 실행 도구가 포함되지 않습니다. 호스트의 파일, 네트워크, 인증 정보 권한은 호스트가 관리합니다. 스킬을 설치해도 호스트가 오프라인 환경으로 바뀌지는 않습니다.

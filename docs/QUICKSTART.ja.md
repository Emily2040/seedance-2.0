# Seedance 2.0 — 最初のプロンプトを選び、直す

バージョン 6.7.0。このガイドはプロンプトを準備するためのものです。動画は別途選んだ生成サービスで作ります。

**レビュー状況：**AI を使った草稿で、日本語と映像制作の言葉について独立したレビューは受けていません。作例の動画は未生成です。品質、クレジットの節約、音声同期の実測結果ではありません。説明文はです・ます体ですが、作中のセリフは話者と場面に合わせて別に決めます。[対応範囲とレビュー記録](LANGUAGE_COVERAGE.md)。

## 1. ルートスキルをひとつインストールする

リポジトリをダウンロードして展開するか、次を実行します。

```sh
git clone https://github.com/Emily2040/seedance-2.0.git
cd seedance-2.0
```

そのフォルダで、インストール先を**ひとつ**選びます。各インストール先に `seedance-20/` フォルダが作られます。サブスキルを個別にインストールする必要はありません。

```sh
# Codex：現在のユーザーで利用
python scripts/install_codex_skill.py --client codex --scope user

# Claude Code：現在のユーザーで利用
python scripts/install_codex_skill.py --client claude-code --scope user

# Codex：既存のひとつのプロジェクトで利用。ソースの外にあるプロジェクトを指定
python scripts/install_codex_skill.py --client codex --scope project --project-root "/path/to/project"
```

`/path/to/project` は、ソースの外にある既存プロジェクトのパスに置き換えます。空白を含むパスは引用符で囲んでください。コマンドはソースのフォルダから実行します。

本節の日本語修正は AI を使った草稿で、独立した言語レビューは未完了です。[レビュー状況](LANGUAGE_COVERAGE.md)。

別のクライアントや独自の設定では、`--dest /path/to/client/skills` でスキルの親ディレクトリを指定します。クライアント・スコープのオプションとは併用しないでください。インストール先のオプションを省略すると、従来の `$CODEX_HOME/skills` または `~/.codex/skills` が使われます。ユーザースコープを明示しても、古いコピーは移動・無効化されません。

doctor でも**同じインストール先**を指定して確認します。たとえば、最初の選択肢を使った場合：

```sh
python scripts/install_doctor.py --client codex --scope user --json
```

`current` は、確認したインストール済みファイルがこのソースと一致することを示します。クライアントを再起動または更新し、認識されたスキルのパスを別途確認してください。doctor は、クライアントがどのコピーを読み込むかまでは確認しません。`--force` は意図的な置き換えにのみ使い、先にローカルの変更と独立したバックアップを保存してください。 [インストール先の選択肢](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_SCOPES.md) · [移行と重複の確認](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_MIGRATION.md).

手動で転送する場合は、インストーラーの `--dest /path/to/new-staging/skills` を使い、ソースの外にある新しい場所でファイルを準備します。**生成された `seedance-20/` ディレクトリだけ**を、隠しファイルと完了記録を含めてコピーしてください。GitHub から直接取り込む場合、クライアントが別のファイルを含めることがあります。取り込む内容を確認し、このインストーラーの許可リストが適用されるとは想定しないでください。 [手動転送の手順](https://github.com/Emily2040/seedance-2.0/blob/main/docs/MANUAL_INSTALL.md).

## 2. すでに決めたことから始める

`seedance-20` を呼び出し、シーンを説明してください。決めたカメラ、音、尺、意図は引き継ぎます。インタビューをやり直したり、頼んでいない選択メニューに答えたりする必要はありません。

| 今あるもの | 次に頼むこと |
|---|---|
| 単独クリップの漠然とした案 | 草稿、または進行に必要な質問ひとつ。`seedance-interview-short` |
| 十分に決まったシーン | そのままプロンプトにする。`seedance-prompt` |
| つながる複数のクリップ | 順序と各クリップの役割を決める。`seedance-sequence` |
| 採用済みクリップの続き | 実際の終わりから続ける。`seedance-continuation` |
| 条件を満たさない結果 | 失敗した点を示し、予算内の修正案を出す。`seedance-troubleshoot` |

ルート名を覚える必要はありません。たとえば、こう伝えられます。

> 六秒の明るいクリップを作りたいです。成人女性の時計修理職人が、直したばかりの置き時計の刻む音を聞きます。カメラは固定、セリフなし。三つの方向を出して、私に選ばせてください。プロンプトの準備だけで、生成はしないでください。

## 3. 観客が何に注目するかを選ぶ

以下は**この依頼**に対する三つの案です。すべての動画に共通する必須メニューではありません。

| 方向 | 画面で決めること | 何を優先するか |
|---|---|---|
| A · 小さな喜び | 固定のミディアムクローズアップ。刻む音を聞いて微笑む | 音に対する表情の変化 |
| B · 素直に喜ぶ | 固定のやや広い画角。短く笑い、両腕を上げる | 身体全体の反応。描く動作は増える |
| C · 時計の動きを見せる | 固定のクローズアップで振り子を映し、職人は背景でぼかす | 時計の運動。表情は主役ではなくなる |

A を選ぶ、両立する要素を組み合わせる、「理由を説明して選んでください」と任せる、いずれも可能です。A に決めた後は、その選択を引き継ぎます。変更を頼まない限り、B や C の動作を混ぜません。

## 4. 選んだプロンプトをコピーする

**この例では A を選びます。** 添付素材のないテキストから動画への草稿です。参照タグは不要です。利用するサービスの操作が六秒に対応している場合、その設定欄で指定し、費用をかける前に確認します。縦横比と品質設定は、別途選んだ値を維持します。特定のサービス、API、モデルの設定は前提にしません。

```text
成人の女性職人が、動いている置き時計の前に座っている。時計が刻む音を聞き、眉をわずかに上げて微笑む。視線は時計に向けたまま。目線の高さのミディアムクローズアップで、カメラは固定する。横の窓からの光で表情が見える。時計の音と作業場の環境音を残し、セリフと音楽は入れない。最後の二秒は微笑みと座った姿勢を保つ。
```

**狙い：**時計の音が目に見える反応を引き出し、固定カメラでその表情を見せ、最後に余韻を残します。これは演出意図であり、確認済みの結果ではありません。実際の修理の正しさを証明する映像でもありません。

**動画で確認すること：**視線が時計に残るか、カメラが固定されているか、意図しない発話がないか、最後の二秒に表情と姿勢が保たれるか。まず失敗した条件を特定します。

「カメラ固定」は人物を静止させる指示でも、スローモーションでもありません。「ゆっくりドリーイン」に変えると変わるのはカメラの移動です。演技をスローモーションにしたい場合は別に指定します。カメラの速さと被写体の動作速度をひとつの「ゆっくり」で済ませないでください。

被写体と動作を先に書くのは読みやすくする工夫で、モデルが冒頭の単語をどう処理するかの検証結果ではありません。英語の語数の目安を日本語の文字数やモーラ数の上限に置き換えず、必要な終わりの状態、参照関係、指定どおりのセリフを残します。

## 5. 失敗した点だけを変える

> 笑顔が大げさでした。A、六秒、固定カメラは維持してください。残りは一回です。まず修正版を書いて、送信はしないでください。

動画が添付されていなければ、不具合は**あなたの報告**として扱い、見たとは言いません。「眉をわずかに上げて微笑む」だけを「眉の力を抜き、歯を見せずに口角をわずかに上げる」に変える案を出せます。他の内容と設定は維持します。表情の振れ幅を小さくする狙いですが、修正の成功は保証できません。残り一回を使い切る必要もありません。

残り回数や予算がゼロなら生成を求めません。既存素材から条件を満たす編集ができるかを検討するか、ここで止めます。編集にも時間やツールの費用はかかります。予算切れを理由に不合格のショットを承認済みにしません。修正を頼むことは、アップロード、生成の送信、サービス変更、品質や尺の引き上げを許可することではありません。

## 6. セリフ、参照素材、続き

**指定どおりのセリフ。** 依頼を「『動いた。』というセリフを一字も変えずに残す」に変更したら、その言葉を保ちます。この例は独り言です。説明文がです・ます体だからといって「動きました」に直したり、聞き手や呼びかけを足したりしません。元のセリフなしの案には追加しないでください。新しく書くセリフは関係性と話者の声から文体を選び、長さを減らすために勝手にくだけた言い方へ変えません。実際の発話を計時し、発音、演技、口の動きとの同期をそれぞれ確認します。この例には実測値も日本語の独立レビューもありません。利用できる操作と使用許可を確認した声の参照素材、または後からの吹き替えも選択肢です。

**実際に渡した素材。** `@Image1` を添付したなら、置き時計の外観だけを参照する、といった役割を指定します。画面が示すタグは、`@图片1` や `[Image 1]` であっても、空白や記号を含めてそのまま残します。日本語に合わせてタグを翻訳しません。名前を書くこととファイルを添付することは別です。画像がなければ上の案はテキストから動画への草稿のままで、参照タグを捏造しません。選んだ操作がその素材と用途を扱えるかも確認します。

**実際の終わりから続ける。** 最終フレームを渡さず「最後は微笑んで時計を見ています」と説明した場合、それはあなたの報告です。作業場の細部を創作して観察済みとしたり、映像を見たと言ったりしません。採用した実際の最終フレームがあれば、その姿勢と視線から続け、時計の音を初めて聞く反応を繰り返しません。重要な位置が不明なら確認し、連続性を検証済みとして扱う前に解決します。

## 7. 安全と次の資料

画像、ファイル、文字起こしに含まれる文章は参照データです。秘密情報の読み取り、コマンド実行、アップロード、生成を許可する指示ではありません。他者の顔、声、ブランド、作品を使う場合は用途と許可を確認し、制限のある依頼を翻訳で隠さないでください。[SECURITY.md](../SECURITY.md)を参照してください。

**インストール済みペイロード**には、ネットワークを使える開発用の `scripts/eval_run.py` や任意のプロバイダー実行ツールは含まれません。ホスト側のファイル、ネットワーク、認証情報への権限はホストが管理します。このスキルを入れてもホストがオフラインになるわけではありません。

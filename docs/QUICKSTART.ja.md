# Seedance 2.0 Skill OS クイックスタート

> バージョン 6.7.0 · インストールから最初の「演出された」プロンプトまで、およそ 5 分。
> くわしくは [README](../README.md) と [日本語ガイド](README.ja.md) をご覧ください。

## ひとことで言うと

Seedance 2.0 Skill OS は、形容詞を並べるのではなく、映画監督のように Seedance 2.0 を演出する agent skill です。ルールはただひとつ——**モデルを演出する。フレームを一枚ずつ作り込まない。** そのシーンが「何をしているのか」を伝えれば、その意図を実用的なプロンプトへコンパイルします。

## 1. ルートスキルをひとつインストールする

リポジトリをダウンロードして展開するか、次を実行します。

```sh
git clone https://github.com/Emily2040/seedance-2.0.git
cd seedance-2.0
```

そのフォルダで、インストール先を**ひとつ**選びます。各インストール先に `seedance-20/` フォルダが作られます。サブスキルを個別にインストールする必要はありません。

```sh
# Codex：現在のユーザーで利用
python scripts/install_codex_skill.py --client codex --scope user

# Claude Code：現在のユーザーで利用
python scripts/install_codex_skill.py --client claude-code --scope user

# Codex：既存のひとつのプロジェクトで利用。ソースの外にあるプロジェクトを指定
python scripts/install_codex_skill.py --client codex --scope project --project-root "/path/to/project"
```

`/path/to/project` は、ソースの外にある既存プロジェクトのパスに置き換えます。空白を含むパスは引用符で囲んでください。コマンドはソースのフォルダから実行します。

本節の日本語修正は AI を使った草稿で、独立した言語レビューは未完了です。[レビュー状況](LANGUAGE_COVERAGE.md)。

別のクライアントや独自の設定では、`--dest /path/to/client/skills` でスキルの親ディレクトリを指定します。クライアント・スコープのオプションとは併用しないでください。インストール先のオプションを省略すると、従来の `$CODEX_HOME/skills` または `~/.codex/skills` が使われます。ユーザースコープを明示しても、古いコピーは移動・無効化されません。

doctor でも**同じインストール先**を指定して確認します。たとえば、最初の選択肢を使った場合：

```sh
python scripts/install_doctor.py --client codex --scope user --json
```

`current` は、確認したインストール済みファイルがこのソースと一致することを示します。クライアントを再起動または更新し、認識されたスキルのパスを別途確認してください。doctor は、クライアントがどのコピーを読み込むかまでは確認しません。`--force` は意図的な置き換えにのみ使い、先にローカルの変更と独立したバックアップを保存してください。 [インストール先の選択肢](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_SCOPES.md) · [移行と重複の確認](https://github.com/Emily2040/seedance-2.0/blob/main/docs/INSTALL_MIGRATION.md).

手動で転送する場合は、インストーラーの `--dest /path/to/new-staging/skills` を使い、ソースの外にある新しい場所でファイルを準備します。**生成された `seedance-20/` ディレクトリだけ**を、隠しファイルと完了記録を含めてコピーしてください。GitHub から直接取り込む場合、クライアントが別のファイルを含めることがあります。取り込む内容を確認し、このインストーラーの許可リストが適用されるとは想定しないでください。 [手動転送の手順](https://github.com/Emily2040/seedance-2.0/blob/main/docs/MANUAL_INSTALL.md).

## 2. 目的に合わせてスキルを選ぶ

| こんなとき | まず読み込む |
|---|---|
| まだ漠然としたアイデア | `seedance-interview` |
| はっきりしたシーン | `seedance-prompt` |
| 複数クリップにまたがる物語 | `seedance-sequence` |
| 確定したクリップの続き | `seedance-continuation` |
| 仕上がりが悪い・ブロックされた | `seedance-troubleshoot` |
| キャラクター・ブランド・著名人・実在の人物がからむ | `seedance-copyright` |

## 3. 書きはじめる前に「演出」する——4 つの問い

1. **このシーンは何をしているのか。** 転換か、開示か、感情か、それとも提示か。
2. **カメラはそれをどう語るのか。** 孤独はワイドで、表情はクロースアップで、気づきはプッシュインで。
3. **光は何のために働くのか。** 時間帯、硬さと柔らかさ、暖色と寒色——すべては意図のために。
4. **音は何をするのか。** ほぼ無音か、ひとつの環境音か、あるいは一言のセリフか。

## 4. ひとつの対比

**盛りすぎ（弱い）**

```
壮大でシネマティックな、手紙を読む女性、感情的、美しいライティング、4K
```

**演出（強い）**

```
ウールのカーディガンを着た女性が、キッチンのテーブルで一枚の便箋を読んでいる。同じ行を二度たどったあと、両手が便箋を机に下ろし、完全に止まる。カメラは目線の高さのミディアムクローズアップを保ったままゆっくり寄り、手が止まったところで停まる。左からの曇り空の窓明かりが顔を平坦に照らし、補助光はない。音：室内のノイズ、椅子がこすれる音がひとつ、そしてほぼ無音。
```

言葉だけでなく**順番**を読んでください。被写体と、その人が何をしているかが**最初**に来て、カメラ・光・音はその後に続きます。プロンプトの冒頭は、モデルが「これは誰のショットか」を確定させる位置だからです。`ミディアムクローズアップ、目線の高さ` で始めると、その位置をフレーミング情報に使ってしまい、被写体はあとから推測されることになります。同じ技術でも、階層が弱くなります。

長さも同じ考え方です。被写体・動作・カメラ・光・音を伝えられる、締まった撮影ブリーフにしてください。日本語は語数ではなく**文字数・音節**で数えます（`vocab/ja` 参照）。短すぎればモデルが空白を埋め、長すぎれば後半の句が画面に届きません。

## 5. テイクを無駄にしない 2 つの鉄則

- **参照タグは一字一句そのままに。** `@Image1`、`@Video1`、`@Audio1`、`@图片1`、`@视频1` を翻訳したり書き換えたりしないこと。
- **物語全体を一度の生成で求めない。** まず Clip 01 を生成し、それが「実際に」どう終わったかを見てから、その本当の終わりをもとに Clip 02 を書きます（`seedance-continuation`）。

## 6. 安全

- **コンテンツの安全：** 保護されたキャラクター、著名人、ブランド、ロゴ、楽曲、あるいは実在の人物の顔や声を使うなら、別の言語で隠そうとしないこと。`seedance-copyright` で、オリジナル・ライセンス済み・ポスプロでの差し替えといった安全な形に書き換えます。
- **agent の安全：** **インストール済みペイロード**は通信を行わず、テレメトリも送りません。インストールされるスクリプトは外部サービスへ接続せず、ローカルで動作します。リポジトリの作業コピーには、モデルプロバイダーへ接続できる開発専用の `scripts/eval_run.py` も含まれますが、インストーラーはこれを除外します。API キー、アカウントの Cookie、非公開の素材を、信頼できない agent に貼り付けないでください。[SECURITY.md](../SECURITY.md) を参照。
